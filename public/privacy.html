Privacy policy

What the desktop app accesses, where your data goes and what you control.

1. About EverySync

EverySync is a Windows desktop application for copying selected application folders, game saves and settings between your PC and local, network or cloud storage that you configure. The project is maintained by Maniots on GitHub.

This policy covers the EverySync desktop application and this project website. The cloud services you connect and GitHub have their own privacy policies. EverySync does not operate a server for receiving your synchronized files, and you do not create an EverySync account.

2. Data the desktop application processes

  • Selected files and folders: file contents, names, paths, sizes, modification times and content hashes used for synchronization, verification, conflict handling, backups and recovery.
  • Connection settings: provider, connection name, selected root folder, service addresses and other settings needed to reach the storage you choose.
  • Authorization credentials: OAuth access and refresh tokens, or other credentials you supply for a supported storage service.
  • Account information: a display name and email address, when supplied by Google, Microsoft or Dropbox, to identify the signed-in account in the interface. These display details are cached in memory while the app is running.
  • Local operational records: configuration, synchronization results, timestamps, paths, error messages, file inventories and recovery state needed to run, diagnose or resume operations.

These data are used to provide the synchronization, backup, recovery and connection features that you request. The application does not include advertising or usage-analytics tracking.

3. Google Drive permissions and use

Google sign-in uses your browser. Google handles your sign-in credentials; EverySync receives authorization tokens and does not receive your Google password.

EverySync requests the Google Drive scope https://www.googleapis.com/auth/drive. This is broad permission to view and manage Drive files, rather than permission restricted to files created by EverySync. It is needed because you can choose existing folders and synchronize their contents. Normal synchronization, backup and recovery operations work with the destinations you configure, including the selected synchronization folders and any configured backup location.

The app also reads the Google account display name and email address through the Drive API to show which account is connected. It does not read Gmail messages, Google Contacts or Calendar data.

Limited Use commitment: EverySync uses Google user data only to provide the synchronization, backup, recovery and connected-account features you request. Google user data is not sold, used for advertising or used to train generalized artificial intelligence or machine-learning models. EverySync’s use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including its Limited Use requirements.

The maintainer does not receive routine access to your Google files or authorization tokens. Do not send them when requesting support.

4. Where data and credentials are stored

File operations run on your PC and use the storage services you select. For an installed app, configuration and runtime data are normally stored under %LOCALAPPDATA%\OneDrivePCSync. Running from source or selecting a custom configuration can use a different local location.

Saved cloud credentials are stored in an encrypted, app-owned rclone configuration. Its encryption password is protected with Windows Data Protection API (DPAPI) for the current Windows user. This protection does not mean that your configuration, logs, history, synchronized files or backups are all encrypted. Their protection also depends on your Windows account, device and chosen storage provider.

Local backup archives and cloud snapshots can contain complete copies of selected files. Keep these storage locations and your Windows account secure.

5. Transfers and sharing

EverySync communicates directly with the storage services you connect to perform the operations you request. Those services receive credentials or tokens needed for authorization, relevant file metadata and the file contents being transferred. Your configured destinations can include Google Drive, OneDrive, Dropbox, S3-compatible storage, SFTP, WebDAV, Azure Blob, Backblaze B2 and local or network folders.

You can configure a download from one service and an upload of the resulting local files to another. Such transfers are performed through your PC at your direction. Do not select destinations that you do not trust or where you are not allowed to store the data.

Your synchronized files are not uploaded to an EverySync-operated server. The maintainer does not sell your Google user data or share it with advertising services. If you voluntarily submit a support request, the information you include is shared with the service used for that request and the people able to access it.

6. Website hosting, updates and support

This website is hosted by GitHub Pages. It uses no advertising, analytics, tracking scripts, remote fonts, forms or browser-storage features. GitHub may process technical request information, including your IP address, to host and secure the website under the GitHub General Privacy Statement.

The desktop updater contacts GitHub to check release information and download updates. GitHub receives the ordinary network information associated with those requests. These update requests do not upload your synchronized files to GitHub.

Links to providers, downloads and support take you to external websites governed by their own policies. GitHub issues are public: do not post tokens, private files, email addresses, configuration files or unredacted logs.

7. Retention, revoking access and deletion

Local configuration and recovery state persist until you remove them. The synchronization history retains the most recent 1,000 runs. The main application log rotates by file size; other runtime logs may also remain. Local backup retention is configurable, and remote snapshots must be managed explicitly. Copies stored in cloud services remain subject to your settings and those services’ retention practices.

Disconnecting: remove the synchronization jobs that depend on a connection before choosing Disconnect account. This removes the selected saved connection and its credentials; it does not delete cloud files, local copies, stored backups or historical records.

Revoking Google access: you can remove EverySync’s authorization from your Google Account’s third-party connections. This prevents further authorized access with that grant, but does not delete copies already stored on your PC or in a destination.

Deleting local data: close EverySync and its background synchronization processes, then remove the application data and any backups or synchronized copies you no longer want. Keep anything you need before deleting it. Updates and uninstalling the app preserve user data; uninstalling alone does not erase it. Delete unwanted remote copies through the relevant storage provider.

The maintainer cannot remotely delete files or credentials held only on your PC or in your cloud accounts.

8. Contact and policy changes

For privacy questions, contact the maintainer through the Maniots GitHub profile or open a general question in the EverySync issue tracker. Public questions should describe the issue without personal data or credentials.

Changes to the application or this website may require updates to this policy. The effective date will be updated here. The policy’s revision history is available in the website repository.
